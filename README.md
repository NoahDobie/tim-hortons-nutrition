# Tim Hortons Nutrition Calculator

A small web app that lets you build a Tim Hortons order and see the combined nutrition for the whole meal — including extras like cream, milk, sugar, and flavoured syrups.

Made by Noah Dobie to help people get a rough idea of what they're eating.

## Disclaimer

This project is **not affiliated with, endorsed by, or sponsored by Tim Hortons** in any way. It was created independently, just to help people out.

Nutrition data is based on publicly available standard formulations from the official Tim Hortons nutrition guide and may not be 100% accurate. Actual values can vary by location, substitution, or how an order is prepared. Always check in-store or on the official Tim Hortons website for the most up-to-date information.

## Features

- Browse the full menu by category and subcategory
- Search across every menu item
- Customize beverages with cream, milk, sugar, and flavoured syrups
- See live, combined nutrition (calories, fat, carbs, protein, sodium, and more)
- Canadian-style Nutrition Facts label with % Daily Value

## Running locally

```bash
npm install
npm run dev
```

Then open the local URL shown in the terminal.

## Tech

React + TypeScript + Vite + Tailwind CSS.

## Updating the menu when Tim Hortons publishes a new PDF

The menu data lives in `src/data/menu.json` and is generated by `extract.py`
from the official Tim Hortons nutrition guide PDF.

When a new edition is published:

1. Drop the new PDF into `nutrition-data/` (and remove the old one).
2. Make sure Python and the PDF parser are installed:
   ```bash
   pip install pdfplumber
   ```
3. Regenerate the menu JSON:
   ```bash
   python extract.py
   ```
   The script auto-detects the PDF in `nutrition-data/` and the effective
   date from its filename. You can also pass them explicitly:
   ```bash
   python extract.py "nutrition-data/Tim Hortons Nutrition Guide - March 2026.pdf" \
       --effective-date "March 2026" --country Canada
   ```
   If Tim Hortons adds a brand-new top-level category, pass it with
   `--extra-category "Name"` (repeatable) so the extractor doesn't mistake
   it for a subcategory.
4. Review the printed per-category / per-subcategory breakdown and the
   resulting `src/data/menu.json` diff — sanity check that totals look
   reasonable and nothing went missing.
5. Open a pull request against `main` with the updated PDF and
   `menu.json`, briefly noting the new edition's effective date in the
   description. **Direct pushes to `main` are not allowed** — all
   updates go through PR review.
